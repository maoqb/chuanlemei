# 需求矩阵

| 编号 | 用户诉求 | Android 首版交付 | 验收方式 | 状态 |
| --- | --- | --- | --- | --- |
| R1 | 在 GitHub 上建源码仓库 | 继续使用 `maoqb/chuanlemei`，源码已替换为 Android 工程 | 访问远程仓库 | 已实现 |
| R2 | 记录每个衣服穿了多少次 | `wear_records` 表保存每次穿着的上衣、裤子、鞋 ID，统计单件总次数和周期次数 | 统计页、单件衣物数据卡 | 已实现 |
| R3 | 支持看历史周期的数据 | 7 天、30 天、90 天、今年、全部、自定义周期 | 统计页切换周期 | 已实现 |
| R4 | 支持看每件衣服的数据 | 选择衣物后展示总次数、最近穿着历史、关联穿搭 | 衣橱/统计页点击衣物 | 已实现 |
| R5 | 基本衣服导入 | 上衣、裤子、鞋分类；名称、主色、品牌、备注、照片 | 衣橱页“选择衣物照片/加入衣橱” | 已实现 |
| R6 | 上衣、裤子和鞋的组合效果 | 组合页按三类选择衣物，展示照片预览和常穿组合 | 组合页操作 | 已实现 |
| R7 | 记录次数必须调用相机拍照 | 使用 `MediaStore.ACTION_IMAGE_CAPTURE` 调起系统相机，返回照片后才可保存记录 | 记录页拍照流程 | 已实现 |
| R8 | 确定日期是否为当天 | 拍照后自动写入本地日期，保存时通过 `DateTools.isToday(recordDate)` 二次校验；跨日则要求重新拍照 | 拍照后查看当天校验状态 | 已实现 |
| R9 | 自动识别是哪件衣服 | `ImageSignature` + `GarmentRecognizer` 按类别输出候选与置信度 | 拍照后查看识别结果 | 已实现 |
| R10 | 输出需求矩阵、方案设计、编码、自测、push | `docs/requirements-matrix.md`、`docs/design.md`、Android 源码、单元测试、远程提交 | 文档、Gradle 测试、GitHub | 已实现 |
| R11 | 使用主流 Android App 导航和交互 | 固定底部四 Tab：首页、衣橱、搭配、统计；页面顶部保留当前上下文和主要操作 | 四个底部 Tab 可切换，主操作始终可见 | 已实现 |
| R12 | 界面达到成熟产品的信息层级 | 首页聚焦今日拍照记录，衣橱使用双列卡片，导入与单件详情使用弹层，搭配使用三段式预览 | 真机检查首页、衣橱、搭配页面 | 已实现 |
| R13 | 统计使用图表而不是文字列表 | 原生 Canvas 柱状图展示周期趋势，环形图展示分类占比，进度条展示衣物排行 | 切换统计周期并查看图表 | 已实现 |

## 非目标

| 编号 | 内容 | 原因 |
| --- | --- | --- |
| N1 | 账号系统和云同步 | 首版先做本地可用，降低隐私和后端成本 |
| N2 | 深度学习级服装识别 | 没有训练集和标注数据，先用可运行的本地相似度算法 |
| N3 | 非当天补录 | 用户明确要求记录次数必须拍照并确定当天，首版强制当天 |
| N4 | 上架发布 | 当前交付 debug APK 和源码，签名发布可后续单独处理 |
